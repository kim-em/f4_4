# Data archive: the complete F-table of C(F4,4)

DOI: **[DATA ARCHIVE DOI: to be supplied]** (Zenodo).

The archive holds the exact data that are too large for the deposit (`../deposit/`). Download its
files into this directory (the default), or anywhere and set

    export F4_ARCHIVE=/path/to/the/files

All programs of `../code/` look for the archive files in `$F4_ARCHIVE`, or in this directory if
the variable is not set. The files are ignored by git.

The archive files are released under the Apache License 2.0 (`../LICENSE`).

| file | content | size (bytes) |
|---|---|---|
| `F4_4_F_part1.bin` | F-table, blocks with first leg `0011`, `0012`, `1010` (11,799 blocks) | 6,496,176,023 |
| `F4_4_F_part2.bin` | F-table, the other 46,941 blocks | 6,454,567,367 |
| `F4_4_R_normalform.txt` | R and Rinv over `Q(zeta_13)` (the uncompressed `../deposit/F4_4_R_normalform.txt.xz`) | 2,160,630 |

All data are in the normal-form gauge of the paper (Section 4.7), in the conventions of the paper
(Section 3). The binary format (`../code/f4/fsym_bin.py`, paper Section 10) stores every entry in the
real basis `1, c_1, ..., c_11` of `Q(zeta_52)^+`, `c_k = zeta^k + zeta^-k`, `zeta = exp(2 pi i/52)`;
every entry lies in `k = Q(zeta_13)^+`. `../code/fields/fsym_k.py` prints chosen blocks, or the
whole table, in the text format of the deposit (basis `eta_j` of `k`):

    python3 code/fields/fsym_k.py archive/F4_4_F_part1.bin archive/F4_4_F_part2.bin 0001,0001,0001,0001

The files `F4_4_F_part{1,2}.bin` and `F4_4_R_normalform.txt` are regenerated byte for byte by the
pipeline of `../code/fields/` (`direct_f4_all.sh`, then `finish_all.sh`; see `../README.md`).
